# S-082 — Fallback offline sob base path e rotas profundas

**Marco:** M6 · **Deps:** S-081 · **Estimativa:** ≤2h, ≤6 arquivos

## Objetivo
Garantir que o app abre sem rede em qualquer rota, também quando publicado em subcaminho (GitHub Pages), e que o SW nunca intercepta Firebase.

## Critérios de aceite (cada um testável automaticamente)
1. AC1 (E2E): com o app servido sob `/sub/` (`VITE_BASE=/sub/` + `vite preview`), após o primeiro carregamento, ficar offline e abrir `/sub/` e uma rota profunda (ex.: aba Histórico) mostra o app, não a página de erro do navegador.
2. AC2 (E2E): o mesmo com base `/` continua passando (`pwa.spec.ts`).
3. AC3: `navigateFallback` resolve para o `index.html` do escopo; `navigateFallbackDenylist` exclui `/__/` (handler de auth do Firebase) e arquivos com extensão.
4. AC4 (E2E): nenhuma requisição para `googleapis.com`/emulador é servida pelo SW (`response.fromServiceWorker() === false`).
5. AC5: GitHub Pages sem SW (primeira visita a rota profunda): `404.html` copia o `index.html` no build para que links profundos funcionem; teste unitário confere que `dist/404.html` existe e é igual.

## Fora de escopo
- Cache de dados (é do Firestore, ADR-0004); prompt de atualização (S-083).

## Notas técnicas
- Projeto Playwright extra ou `webServer` adicional com base `/sub/`; manter só os testes PWA nele para não dobrar o tempo.
- Se o roteamento for por estado (sem URL), AC1 testa só `/sub/` e `/sub/index.html` e o AC5 vira "não aplicável" registrado no PR.
