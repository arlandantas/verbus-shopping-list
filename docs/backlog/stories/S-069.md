# S-069 — Overlay: sheet e diálogos fecham sozinhos em dev (StrictMode)

**Marco:** UX2 · **Deps:** — · **Estimativa:** ≤3h, ≤4 arquivos

## Ler antes (somente estes)
- docs/rules/frontend.md · docs/rules/testing.md
- src/components/m3/Overlay.tsx, src/main.tsx

## Objetivo
Corrigir o bug reportado: no `pnpm dev:local` o botão editar abre o sheet e ele fecha na hora (também Dialog de sair, "Entenda melhor", excluir). Causa medida: sob StrictMode o cleanup chama `history.back()` (assíncrono) e o effect re-roda e dá novo `pushState`; o popstate tardio fecha o overlay (Overlay.tsx:42-80).

## Critérios de aceite
1. AC1 (unit): renderizar um `BottomSheet` e um `Dialog` dentro de `<StrictMode>` mantém-nos abertos após o flush dos effects e de um popstate pendente.
2. AC2 (unit): voltar do Android (popstate real) ainda fecha o overlay topo; fechar pelo app não deixa entrada de histórico órfã.
3. AC3 (E2E, novo `tests/e2e/overlay-dev.spec.ts`): contra o servidor de desenvolvimento do Vite (StrictMode ativo; o E2E atual roda `vite preview`, onde StrictMode não duplica effects, por isso o bug passou), tocar "Editar {nome}" abre o sheet e ele permanece aberto; Cancelar fecha.
4. AC4: `pnpm test:e2e` completo verde.

## Notas técnicas
- Sem timers. Ideia: marcar no token do overlay que o cleanup veio de remount e só chamar `history.back()` se o overlay for desmontado de fato (ex.: adiar o back para o fim do tick e cancelar se o mesmo token for re-registrado).
- Configurar o projeto Playwright extra para o dev server (porta 5173 do dev:local, já ativo, `reuseExistingServer`).
