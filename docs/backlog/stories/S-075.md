## Objetivo
Provar com testes de emulador que ninguém fora de `members` lê, lista ou escreve dados de uma família, e que não dá para enumerar famílias, usuários ou convites. Corrigir `firestore.rules` se algum teste falhar.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: Para cada subcoleção (`items`, `catalog`, `categories`, `members`, `purchases`, `purchaseLines`, `cycles`), um teste tabelado nega `get`, `list`, `create`, `update` e `delete` a: não autenticado, autenticado sem família e membro de outra família.
2. AC2: `collectionGroup` em cada subcoleção, sem filtro de família, é negado para membro de qualquer família.
3. AC3: `list` de `families` sem `where('members','array-contains', uid)` é negado; com o filtro do próprio uid é permitido; com o uid de outra pessoa é negado.
4. AC4: `list` de `invites` e de `users` é negado; `get` de `users/{outro}` é negado.
5. AC5: Acesso a `families/{inexistente}/items/x` é negado (sem erro de regra que vaze permissão).
6. AC6: Ex-membro removido manualmente do array (via admin no teste) perde leitura e escrita imediatamente.
7. AC7: `pnpm test:rules` verde; nenhum teste existente alterado para passar.
