# S-006 — CI no GitHub Actions

**Marco:** M0 · **Deps:** S-002, S-005 · **Estimativa:** ≤1h, ≤2 arquivos

## Ler antes (somente estes)
- docs/adr/0006-emulator-and-ci.md

## Objetivo
Workflow que roda `pnpm check` e `pnpm test:e2e` em push e PR, sem segredos.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: `.github/workflows/ci.yml` passa no `actionlint` (rodar via `pnpm dlx` ou binário do Go; se indisponível, validar YAML e registrar em nota).
2. AC2: o job usa Node 22, pnpm (via `pnpm/action-setup` lendo `packageManager`), JDK 21 temurin, cache do pnpm e de `~/.cache/firebase/emulators`.
3. AC3: passos na ordem: install `--frozen-lockfile` → `pnpm check` → `playwright install --with-deps chromium` → `pnpm test:e2e`; upload do `playwright-report/` em falha.
4. AC4: nenhum `secrets.*` referenciado no workflow.
5. AC5: reproduzir localmente a sequência do AC3 termina com código 0.

## Fora de escopo
- Deploy automático (adiado; ver S-013).

## Notas técnicas
- **Input do usuário (não bloqueante):** para o CI rodar de fato é preciso um repositório remoto no GitHub e `git push`. A história é concluída com a validação local; a primeira execução real fica para quando o usuário criar o remoto.
