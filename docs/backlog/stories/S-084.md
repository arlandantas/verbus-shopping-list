## Objetivo
GitHub Pages não permite cabeçalhos: injetar no build uma `Content-Security-Policy` via `<meta>` que libera só o necessário para Firebase Auth/Firestore, e uma política de referrer.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: plugin Vite (`transformIndexHtml`) injeta a meta CSP montada a partir das variáveis `VITE_FIREBASE_*` (authDomain); build de emulador (`VITE_USE_EMULATOR=true`) acrescenta só `http://127.0.0.1:*` e `http://localhost:*` em `connect-src`.
2. AC2 (unit): função pura `buildCsp({ authDomain, emulator })` retorna `default-src 'self'`, `script-src 'self'` (+ `https://apis.google.com` só se necessário ao login Google), `connect-src` com `firestore.googleapis.com`, `identitytoolkit.googleapis.com`, `securetoken.googleapis.com` e `https://<authDomain>`, `frame-src https://<authDomain>`, `img-src 'self' data:`, `object-src 'none'`, `base-uri 'self'`; nunca `unsafe-eval` nem `unsafe-inline` em `script-src`.
3. AC3: `<meta name="referrer" content="strict-origin-when-cross-origin">` presente no `dist/index.html`.
4. AC4 (E2E): fluxo login (emulador) → lista → adicionar item → aba Família roda sem nenhum evento `securitypolicyviolation` (escutar via `page.addInitScript`).
5. AC5: `pnpm dev` (servidor Vite) não recebe a CSP, para não quebrar HMR.
6. AC6: nova ADR curta registra as origens liberadas e o risco aceito de `frame-ancestors` (não funciona em meta) no GitHub Pages.

## Fora de escopo
- Cabeçalhos HTTP (exigiriam outra hospedagem); Trusted Types.

## Notas técnicas
- `style-src` pode precisar de `'unsafe-inline'` (estilos inline do React/Tailwind); aceitável, documentar na ADR.
- Plugin em `scripts/` ou `vite/csp.ts`; teste unitário da função pura em `tests/`.
- O SW (`sw.js`, workbox) é `'self'`; conferir `worker-src 'self'`.
