## Objetivo
Atacar o fluxo de convite/entrada (`invites`, `validJoin`, `validFamilyCreate`) e fechar qualquer brecha com teste de negar.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: Entrar na família A usando `joinCode` de convite da família B é negado.
2. AC2: Entrar com código inexistente, mal formado (minúsculas, 7/9 chars, `0`, `O`, `I`, `L`, `1`) é negado.
3. AC3: Entrar já sendo membro de outra família (perfil com `familyId`) é negado; entrar sem o perfil no mesmo lote é negado.
4. AC4: Entrar adicionando outro uid, dois uids, ou reordenando/removendo membros é negado; 11º membro é negado.
5. AC5: Criar convite para família da qual não é membro, com `familyName` diferente do nome real, ou com `createdBy` de outro é negado.
6. AC6: Criar família apontando para convite de outra família ou criado por outro uid é negado; sobrescrever (`create` sobre id existente) convite alheio é negado.
7. AC7: Não membro não apaga convite; `update` de convite é sempre negado.
8. AC8: `pnpm test:rules` verde.

## Fora de escopo
- Trocar o código (rotação): S-077. Expiração de convite: não (família é grupo de confiança, ADR-0016).
