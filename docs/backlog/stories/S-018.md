## Objetivo
Repositórios `src/data/items.ts` e `src/data/catalog.ts` que as telas do M2 (e M4) usam, com escritas sem `await` na UI.

## Critérios de aceite (todos via `pnpm test:data`, `tests/data/items.test.ts`)
1. AC1: `addItem(familyId, { name, quantity, unit, note?, categoryId?, recurring? })` grava, num só `writeBatch`, o item (`nameKey` via `toNameKey`, `pending`, nulls) e o `catalog/{nameKey}`; retorna o id do item sem esperar o servidor.
2. AC2: `watchItems(familyId, cb)` entrega `Item[]` com `includeMetadataChanges` e `hasPendingWrites` por item; pendentes por `createdAt`, comprados por `markedAt` (estimativa para timestamps pendentes).
3. AC3: `updateItemDetails(familyId, id, patch)` faz update só dos campos alterados; se `quantity`/`unit`/`categoryId` mudam, atualiza o catálogo no mesmo batch.
4. AC4: `setItemStatus(familyId, id, 'bought' | 'pending')` grava só `status`, `markedBy`, `markedAt`; `deleteItem` apaga.
5. AC5: `watchCatalog(familyId, cb)` entrega `CatalogEntry[]`; adicionar "Feijão" e depois "feijao" resulta em um só doc no catálogo com `name: 'feijao'`.
6. AC6: um segundo usuário de outra família recebe erro de permissão em `watchItems` da família alheia.
