# S-085 — CI: varredura de segredos e auditoria de dependências

**Marco:** SEC · **Deps:** — · **Estimativa:** ≤2h, ≤6 arquivos

- docs/spec/85-security.md

## Objetivo
Impedir que segredo entre no repositório e que dependência de produção com vulnerabilidade alta passe pelo CI.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: job no `.github/workflows/ci.yml` roda varredura de segredos no histórico (ex.: `gitleaks/gitleaks-action` com `fetch-depth: 0`) e falha se achar algo.
2. AC2: `.gitleaks.toml` (se preciso) libera só a config web pública do Firebase (`apiKey` `AIza...` em `.env.example`/docs) e chaves fictícias do emulador; comentário explica por que não é segredo.
3. AC3: script `pnpm audit:ci` = `pnpm audit --prod --audit-level high`; o job do CI falha se ele falhar. Rodado localmente agora: verde, ou dependências atualizadas na mesma história.
4. AC4: `.gitignore` cobre `.env*.local`, `*.pem`, `service-account*.json`, `firebase-debug*.log`; teste unitário (`tests/repo-hygiene.test.ts`) confere essas linhas e que nenhum arquivo rastreado (`git ls-files`) casa com esses padrões.
5. AC5: `deploy-pages.yml` lê a config do Firebase de `vars`/`secrets` do GitHub, nunca de arquivo commitado; teste unitário verifica que o workflow não contém `AIza`.
6. AC6: Dependabot (`.github/dependabot.yml`) semanal para `npm` e `github-actions`.

## Fora de escopo
- Auditoria de dependências de desenvolvimento como bloqueante (só relatório).

## Notas técnicas
- Ação de terceiros fixada por SHA de commit.
- Se `gitleaks` achar algo real no histórico: parar e avisar o usuário (rotacionar credencial é input dele).
