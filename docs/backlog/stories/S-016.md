# S-016 — Regras: `catalog` (fonte do autocompletar)

**Marco:** M2 · **Deps:** S-015 · **Estimativa:** ≤2h, ≤2 arquivos

## Ler antes (somente estes)
- docs/adr/0009-catalog-autocomplete-and-cycles.md
- docs/adr/0008-items-model-and-rules.md (formas de `quantity`, `unit`, `categoryId`, `nameKey`)
- docs/rules/firestore.md, docs/rules/testing.md

## Objetivo
Membros leem e gravam `families/{F}/catalog/{nameKey}` com forma válida, inclusive no mesmo batch que cria o item.

## Critérios de aceite (todos via `pnpm test:rules`, arquivo `tests/rules/catalog.test.ts`)
1. AC1: membro faz `set` válido (create) e `set` de novo no mesmo id (update); `get` e `list` permitidos ao membro.
2. AC2: negado: id fora do regex de `nameKey` ou `nameKey` ≠ id; chave extra/faltando; `quantity`/`unit`/`categoryId` inválidos; `lastUsedAt` ≠ `request.time`; `name` vazio ou >80.
3. AC3: `delete` negado até para membro.
4. AC4: não membro, anônimo e outra família negados em leitura e escrita.
5. AC5: batch "adicionar" (create de item válido + `set` do catálogo) permitido; com catálogo inválido o batch inteiro falha.

## Fora de escopo
- Esquecer sugestão (delete). Camada de dados (S-018).
