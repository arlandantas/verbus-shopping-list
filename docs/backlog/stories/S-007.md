# S-007 — Regras: `users` e `families` (criar e ler)

**Marco:** M1 · **Deps:** S-003 · **Estimativa:** ≤3h, ≤4 arquivos

## Ler antes (somente estes)
- docs/adr/0003-firestore-model-and-rules.md
- docs/rules/firestore.md, docs/rules/testing.md

## Objetivo
Regras de segurança para perfil do usuário, criação de família e acesso de membros, com testes de permitir e negar.

## Critérios de aceite (cada um testável automaticamente; todos via `pnpm test:rules`)
1. AC1: usuário lê/cria/atualiza só `users/{seuUid}`; ler ou escrever `users/{outro}` é negado; não autenticado negado.
2. AC2: `users` aceita só as chaves `displayName`, `email`, `familyId`, `createdAt` com tipos corretos; chave extra negada.
3. AC3: criar `families/{id}` é permitido só com `members == [uid]`, `ownerId == uid`, `name` string 1–60 caracteres e chaves da ADR-0003; `members` com outro uid é negado.
4. AC4: membro lê `families/{id}` e qualquer doc em `families/{id}/items/x`; não membro é negado (inclusive membro de outra família — teste entre famílias).
5. AC5: setar `users/{uid}.familyId = F` só é permitido se `getAfter(families/F).members` contém o uid (teste em batch com criação da família; e negado para família alheia).
6. AC6: `delete` de `families/{id}` negado para todos no MVP; caminhos fora do modelo negados.

## Fora de escopo
- Convites e entrar em família (S-008). Validação de forma de `items` (M2).
