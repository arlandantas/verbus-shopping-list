# S-013 — Projeto Firebase real e deploy manual

**Marco:** M1 · **Deps:** S-012 · **Estimativa:** ≤2h, ≤5 arquivos

## Ler antes (somente estes)
- docs/adr/0006-emulator-and-ci.md
- docs/rules/firestore.md

## Objetivo
Ligar o app a um projeto Firebase real e publicar regras + Hosting, para o casal testar em celulares reais.

## Input do usuário necessário (o gestor pede antes de iniciar; as histórias do M2 podem seguir em paralelo)
1. Criar o projeto no console Firebase (sugestão de região do Firestore: `southamerica-east1`) e informar o **project ID**.
2. Ativar Authentication → provedores **Google** e **E-mail/senha**.
3. Criar o app Web e colar a config pública (`apiKey`, `authDomain`, `projectId`, `appId`...) — não é segredo, mas fica em `.env.production` (não versionado).
4. Rodar `pnpm firebase login` na própria máquina (o agente nunca digita credenciais).

## Critérios de aceite (cada um testável automaticamente)
1. AC1: `.firebaserc` tem alias `prod` → project ID real; `default` continua `demo-verbus` (testes inalterados).
2. AC2: `pnpm build` com `.env.production` gera bundle sem `VITE_USE_EMULATOR` e sem `demo-verbus` (teste/grep no `dist/`).
3. AC3: script `deploy` = `pnpm build && firebase deploy --project prod --only hosting,firestore:rules`; `firestore.indexes.json` presente.
4. AC4: `.env.example` documenta as chaves `VITE_FIREBASE_*`; nenhum valor real versionado (`git grep` pelo project ID real só em `.firebaserc`).
5. AC5: após deploy, `curl -sI https://<projeto>.web.app` retorna 200 e o manifest é servido.

## Fora de escopo
- Deploy no CI, domínio próprio, App Check.
