# S-081 — Manifest e metas Apple coerentes com o tema e o base path

**Marco:** M6 · **Deps:** S-080 · **Estimativa:** ≤2h, ≤6 arquivos

## Objetivo
Polir o manifest e o `index.html` sem input do usuário: cores iguais ao tema M3, metadados completos e ícones Apple, tudo funcionando sob `VITE_BASE`.

## Critérios de aceite (cada um testável automaticamente)
1. AC1: manifest tem `id` (= base), `description` pt-BR, `orientation: 'portrait'`, `theme_color` e `background_color` iguais às cores claras das `meta theme-color` do `index.html` (hoje `#16a34a` diverge de `#fbf8ff`).
2. AC2: `index.html` tem `<link rel="apple-touch-icon">` (192px provisório), `<meta name="apple-mobile-web-app-title" content="Compras">`, `apple-mobile-web-app-status-bar-style`, `<meta name="description">` e `<link rel="icon">`, todos com URL relativa ao base (sem `/` fixo).
3. AC3 (unit em `tests/`): build com `VITE_BASE=/sub/` gera `dist/manifest.webmanifest` com `start_url`, `scope`, `id` e ícones resolvendo sob `/sub/`, e `dist/index.html` com links sob `/sub/`.
4. AC4 (E2E `pwa.spec.ts`): manifest acessível com os campos de AC1, SW ativo, reload offline funciona (checagem PWA da regra de front-end).
5. AC5: ícones continuam os provisórios (`scripts/gen-icons.mjs`); nenhum arquivo de ícone novo exigido do usuário.

## Fora de escopo
- Ícones definitivos, splash screens iOS por resolução.

## Notas técnicas
- Mexer em `vite.config.ts` (manifest), `index.html`; Vite reescreve URLs absolutas do `index.html` com o base, mas `href` para `public/` deve ser testado.
- Se AC3 exigir build no teste unitário, marcar como teste lento ou executar via script no CI.
