## Objetivo
Hoje `registerType: 'autoUpdate'` pode recarregar a página no meio da compra. Trocar para aviso: snackbar "Nova versão disponível" com "Atualizar".

## Critérios de aceite (cada um testável automaticamente)
1. AC1: `vite.config.ts` usa `registerType: 'prompt'`; o registro vem de `virtual:pwa-register/react` (sem script inline, compatível com a CSP de S-084).
2. AC2 (componente, hook mockado): com `needRefresh = true` aparece snackbar pt-BR "Nova versão disponível" com ação "Atualizar"; tocar chama `updateServiceWorker(true)`; fechar esconde até a próxima detecção.
3. AC3 (componente): com `offlineReady = true` aparece uma vez "Pronto para usar sem internet" e some sozinho.
4. AC4: checagem de atualização ao voltar o app para frente (`visibilitychange`) e no máximo a cada 60 min; teste com timers falsos.
5. AC5: snackbar usa o empilhamento de avisos existente (S-072) e não cobre a barra de adicionar.
6. AC6 (E2E `pwa.spec.ts`): SW continua ativo e o reload offline continua funcionando com `prompt`.

## Fora de escopo
- E2E real de duas versões do SW (frágil); notas de versão.

## Notas técnicas
- Componente `src/components/UpdatePrompt.tsx` montado no shell; strings no módulo de strings.
- Escritas pendentes do Firestore sobrevivem ao reload (persistência IndexedDB, ADR-0004), então "Atualizar" não precisa de confirmação extra.
- Garantir tipos: `vite-plugin-pwa/react` em `tsconfig`/`vite-env.d.ts`.
